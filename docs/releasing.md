# ZoneSwitch 发布检查清单

准备版本：`0.1.0`。本清单用于发布前验收，不表示已经上线。

发布时区分源码发版与生产部署：只发布源码版本时，在 GitHub Release 中明确记录未部署和未完成的线上验收项；用户同时授权生产部署时，执行下面的部署及线上验收步骤。不得将 GitHub Release 发布成功表述为 Cloudflare 已上线。

## 分支约定

- `main`：日常开发分支，执行 CI 检查。
- `release`：生产发布分支。人工验收后，将已确认的版本合入此分支。
- GitHub Actions 只允许 `release` 自动部署；Cloudflare Workers Builds 的三个 Worker 也选择 `release` 为生产分支。同一套 Worker 只启用一种部署方式。
- 按功能使用中文提交信息。提交、推送、线上部署、标签及 GitHub Release 均按用户明确确认的范围执行。
- 每次正式发布都必须在 GitHub Release 页面填写整理后的中文更新内容，不能只发布标签。版本说明保存在 `docs/releases/<版本>.md`，与 `CHANGELOG.md` 一起维护。

## 本地检查

使用 Node.js 24，在项目根目录执行：

```sh
npm ci
npm test
npm run build:ci
npm run dry-run:all
```

- [ ] 依赖可按锁文件安装，`package.json` 与锁文件版本一致。
- [ ] 回归测试通过。
- [ ] 前后端类型检查和前端生产构建通过。
- [ ] 维护页、欠费页、后台三个 Worker 的 dry-run 打包通过。
- [ ] README、部署文档的相对链接、章节锚点和截图正常。
- [ ] 对照待提交文件清单，确认没有 `.dev.vars`、`.env`、Token、密码、个人部署参数、日志、本地状态或构建产物。
- [ ] 新增界面截图经过逐张检查，不含账号、邮箱、头像、Account ID、仓库归属、个人域名或密钥值。

`npm test` 使用模拟 API 和内存存储；dry-run 不上传。这些检查不能替代真实 Cloudflare 环境的验收。

## 人工验收

- [ ] 登录、退出、过期会话，以及简体中文 / 英文切换。
- [ ] 域名同步、筛选、跨域选择、确认弹窗和操作记录。
- [ ] 在非关键业务域名验证维护、欠费与恢复，分别覆盖 Worker 自定义域名和服务器代理入口。
- [ ] 核对原 DNS 与业务 Custom Domain 未被更改，恢复后临时路由被正确移除或建立通配例外。
- [ ] 验证真实业务域名首页与深层路径，以及繁体中文 / 日文 / 英文提示。
- [ ] 遇到失败或“待核实”时，核对同步后的真实路由状态；不把部分成功视为整批成功。

真实账号下的路由操作会影响业务入口，应在明确授权的环境与域名上验收。

## 发布步骤

1. 完成人工验收，按功能使用中文提交信息整理提交，将确认的版本合入 `release`。
2. 核对 `package.json`、`package-lock.json` 和[更新记录](../CHANGELOG.md)的版本一致。
3. 按所选的[中文部署指南](deployment.md)或[英文部署指南](deployment.en.md)配置生产分支、Worker 名称、运行参数与部署身份。
4. 获得明确发布授权后推送 `release`。若此次包含生产部署，在所选平台确认三个 Worker 的更新结果；未变化项允许明确跳过。只发布源码且尚未配置部署时，CI 检查通过后继续发版，并明确记录未部署。
5. 此次包含生产部署时，完成部署后人工验收，记录实际部署的提交版本。部分失败时修复并重试，不删除 DO 或路由归属数据。
6. 核对上一正式版本到本次版本的全部变化，按“新增 / 优化增强 / 修复 / 删除”整理中文说明；没有相关变化时写“无”。首次发布说明覆盖首版功能，后续发布只描述版本间变化。
7. 确认发布成功后填写真实发布日期，将“待发布”更新为正式记录。核对 [`releases/v0.1.0.md`](releases/v0.1.0.md)，删除草稿提示并填写真实验证结果，再按授权创建 `v0.1.0` 标签和 GitHub Release，将说明正文完整填入 Release 页面。
8. 读取 GitHub Release 页面，确认版本、目标提交和更新内容均正确，再向用户提供发布链接。不能将只写在本地的说明当作已更新 GitHub Release。

首次配置、上游更新、增量部署和恢复边界以部署指南为准。不要为了发布而清除 `.wrangler/state/`、替换已有 Worker / DO 身份或公开个人配置。
